## ب) مراجعة هندسية — أخطاء وثغرات وأداء

### أخطاء / فجوات وظيفية
1. **نموذج EOI في `apply.html` لا يستدعي الـ API** — يعتمد على `data-validate` المحلي فقط؛ يجب ربطه بـ `EoiAPI.submit()` بعد تسجيل الدخول.
2. **لا يوجد تحقق من البريد (Email verification)** — الحساب يُفعَّل فوراً.
3. **لا يوجد Refresh Token** — JWT لمدة 7 أيام فقط؛ عند الانتهاء يُطرد المستخدم دون تجديد صامت.
4. **رفع الملفات غير منفّذ** — جدول `eoi_attachments` موجود لكن لا يوجد route للرفع.
5. **لوحة الإدارة غير موجودة** — المراجعون (`role: reviewer/admin`) بلا واجهة.
6. **بيانات الطقس Demo** — ليست حية؛ Widget طقس العرب يحتاج لصق يدوي.

### ثغرات أمنية
| الخطورة | الثغرة | التوصية |
|---------|--------|---------|
| عالية | `JWT_SECRET` الافتراضي في الكود | إجبار قيمة عشوائية ≥32 بايت عبر `.env` ورفض التشغيل بدونها |
| عالية | لا يوجد حماية CSRF للجلسات القائمة على الكوكيز (حالياً Bearer فقط — أقل خطورة) | الإبقاء على Bearer أو إضافة double-submit cookie |
| متوسطة | Rate limit عام 200/15د قد يكون مرتفعاً لـ auth | فصل limit أشد لمسارات auth (موجود جزئياً: 10/15د) |
| متوسطة | لا يوجد helmet CSP صارم | تفعيل `Content-Security-Policy` |
| متوسطة | رسائل الخطأ قد تكشف وجود البريد (`EMAIL_EXISTS`) | توحيد الرسالة: «إذا كان البريد مسجلاً...» |
| منخفضة | CORS origins ثابتة في التطوير | قائمة بيضاء من `.env` في الإنتاج |
| منخفضة | لا يوجد `httpOnly` للكوكيز (التوكن في localStorage) | التفكير في cookie آمن + CSRF لاحقاً |

### أداء
- CSS واحد كبير غير مُصغَّر (~1000 سطر)
- خط Cairo من Google Fonts بدون `font-display: swap` صريح في الرابط (يُفضّل إضافته)
- لا يوجد lazy-load للصور (لا صور كثيرة حالياً)
- العدّاد يعمل كل ثانية — مقبول
- لا يوجد Service Worker / Caching

### تحسينات مقترحة (مرتبة بالأولوية)
1. ربط نموذج التقديم بالـ API + إجبار تسجيل الدخول
2. تقوية JWT_SECRET ورفض الإقلاع بالقيمة الافتراضية
3. تفعيل CSP وHelmet كامل
4. إضافة `font-display=swap` وضغط CSS/JS
5. Email verification + إعادة تعيين كلمة المرور
6. لوحة مراجعة للإدارة
7. اختبارات وحدة لمسارات auth و eoi
8. مراقبة أخطاء (Sentry) وسجلات منظمة
